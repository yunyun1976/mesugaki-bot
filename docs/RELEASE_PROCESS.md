# リリースプロセス・マニュアル

このドキュメントでは、本プロジェクトにおけるリリースの手順について説明します。
GitHub Actionsによる自動化（Release Drafter）を活用し、安全かつ効率的なリリースを目指します。

---

## 1. 開発とブランチ運用

1.  **機能開発:** `feature/xxx` や `fix/xxx` ブランチで作業を行います。
2.  **developへの統合:** 作業完了後、`develop` ブランチに対してプルリクエスト（PR）を作成し、マージします。

## 2. リリースの準備（develop -> main）

1.  **PRの作成:** `develop` ブランチから `main` ブランチに対してプルリクエストを作成します。
2.  **Issueの紐付け:** PRの本文（Description）に、今回クローズするIssue番号を記述します。
    *   例: `Closes #123`, `Fixes #456`
    *   これを記述することで、`main` へのマージ時にIssueが自動的にクローズされます。
3.  **下書きの自動生成:** PRを作成（または更新）すると、GitHub Actionsが自動的に動作し、リリースページに **Draft（下書き）** が作成または更新されます。

## 3. リリースの確認と編集

1.  リポジトリの **[Releases]** ページを確認します。
2.  `vX.X.X` のような名前の **Draft** が存在することを確認し、[Edit] ボタンを押します。
3.  自動生成された変更点（Changes）を確認し、「開発者コメント」セクションに補足情報を記述します。

## 4. リリースの公開

1.  下書きの内容が問題なければ、**[Publish release]** ボタンを押します。
2.  これにより、Gitタグが自動的に生成され、正式なリリースとして公開されます。
3.  同時に、PRで紐付けたIssueが自動的にクローズされます。

---

## 💡 ダウンロード数バッジについて

`README.md` のダウンロード数バッジは、GitHubのリリースページに **Assets（ビルド済みのファイルやzipなど）** が添付されている場合にカウントされます。ソースコードのみのリリースの場合は、数値が反映されない場合があるため注意してください。
