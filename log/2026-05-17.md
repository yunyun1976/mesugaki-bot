### 2. 低スペック環境向けタイムアウト対策の実施
- Raspberry Pi Zero WHなどの低スペックハードウェアにおいて、Discordの3秒ルール（インタラクション・タイムアウト）によりコマンドが失敗する問題を修正した。
- `src/main.py`の`global_interaction_check`にて、インタラクション受信直後に最優先で`defer()`を呼び出す「早期デファー戦略」を実装した。
- 公開コマンド（`batou`, `wakarase`）と非公開コマンド（管理系, `help`）で、`defer()`の`ephemeral`フラグを動的に切り替えるようにした。
- すべてのCog（`admin.py`, `messaging.py`, `help.py`）から個別の`defer()`や`send_message()`を排除し、`followup.send()`を使用するように統一した。
- 深夜帯の「おやすみモード」判定においても、判定処理の前に`defer()`を行うことでタイムアウトを防止した。

### 3. テスト用Docker環境の構築
- 低スペック環境の挙動をPC上で再現するための`Dockerfile.repro`を作成した。
- `uv`パッケージマネージャーをDockerビルド時に正しく導入するための最適化を行った。
- DockerのCPU制限（`--cpus=".1"`）とメモリ制限（`--memory="512m"`）を併用し、擬似的にPi Zero WH相当の負荷環境で動作検証を行う手法を確立した。
- `docs/DOCKER_SETUP.md`を作成し、上記環境の起動方法をドキュメント化した。

### 4. Pythonのバージョンを3.15に設定

### 4. 語彙削除ロジックのバグ修正
- `/remove_batou` および `/remove_wakarase` コマンドにおいて、DBからは削除されているにもかかわらず失敗メッセージが表示される問題を修正した。
- `src/libs/db_handler.py` の `remove_phrase` 関数にて、削除成功判定を `c.rowcount` から `conn.total_changes` に変更し、SQLiteにおける削除件数の取得を確実にした。
